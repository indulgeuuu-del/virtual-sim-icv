# 驾驶与泊车开发模块

所有队员在本目录共同开发。`TrajectoryControl`负责驾驶，`AVP`负责泊车，`util`提供共享工具。首次环境配置和提交方法见[团队指南](../docs/team/README.md)，实质进度见[开发进度](../docs/team/开发进度.md)。

## 来源与边界

`baseline.json`记录77个继承文件的原路径、原始SHA-256和大小，来源提交可在Git历史中定位。原目录保留作比较，修改在本目录进行；第三方声明保留在原文件中，没有新增覆盖全部代码的统一许可证。未复制IDE缓存与编译产物。

两份CMakeLists需要匹配的SimOne SDK上层工程、头文件、库和构建辅助函数，不能单独执行CMake就得到参赛程序。旧的`SIMONE_ADAS_DIR`仍是固定配置根目录，AVP也通过它读取驾驶配置；正式接入前须统一配置并验证，不能假设改完本目录后旧程序就会自动读到这里的文件。旧地图坐标、案例编号和车辆参数均须在本届环境核对，`41.stg`不表示本届评分41已适配。

## 先理解一条策略怎样执行

阅读顺序：`TrajectoryControl/src/main.cpp`的`loadJson()`与模式选择 → `src/manual/manual.cpp`的`loadStrategyPoints()` → `src/main_manual.cpp`的逐帧循环。这里的manual是预设策略点驾驶，不是键盘遥控。

策略文件格式为`[id, x, y, pathMode, stopTime, speed, kp]`。例如：

```json
{"strategy": [[0, 100, 0, -1, 0.5, 6, -1]]}
```

这条示例让程序以世界坐标`(100,0)`为目标，用平台路线规划（pathMode=-1），到达判定范围时发出停车命令，计时0.5秒后恢复6m/s目标速度，转向比例系数kp沿用默认值。6m/s等于21.6km/h。它是解释格式的示例，不是比赛地图配置，也不证明车辆实际已经静止0.5秒。

1. 配置读取后形成`strategyPoint`列表。C++列表第一个元素编号是0，列表编号与文件中的id字段不能混为一谈。
2. `main_manual()`先拒绝空列表，将`currentIdx`设为0。它表示“当前处理哪一个目标点”。
3. 每帧取得车的位置，根据当前点读取速度、转向系数和停车时间；字段为-1时使用该字段的默认行为。
4. `firstPointPending`记录“还没为第一个点建立路径”。它与点编号分开：即使车已经靠近第一个点，首帧也先为它建立路径。
5. 后续帧依据距离和停车状态决定是否切换下一点，再由`drive()`向平台发送控制，`NextFrame()`结束本帧。

在Speed控制模式下，`throttle`写入的是目标速度m/s。平台如何将目标速度变成真实加减速，需要真实环境验证。

## 本次修复的原因

旧循环先设`currentIdx=-1`，随即通过宏读取`strategyPoint[currentIdx]`中的kp和stopTime，之后才把编号改成0。这属于越界读取：程序可能崩溃，也可能读到错误数值，不能认为每次都必然崩溃。

修复把编号初始化提前，并用独立布尔值保留首帧建路流程；编号使用函数内普通变量，使再次进入模式时从首点开始。空列表在等待平台帧之前返回错误码1，交给现有调用者检查。`stopTime`由int改为double，避免把配置的0.5秒截成0秒。

修改只涉及该循环。策略解析器的列数/空内容验证、路径生成失败处理、切换点当帧的参数与路径一致性，以及基于真实静止状态和仿真时钟的停车计时，仍需分别验证和完善。现有计时器使用计算机时钟，本次保留此行为。

## 在自己的电脑上验证

前提：Windows、Git、Python 3.10 Launcher、Visual Studio“使用C++的桌面开发”工作负载。按团队指南完成安装后，在包含根README、tools和tests的仓库目录打开PowerShell。

```powershell
git pull --ff-only origin main
py -3.10 tools/test_competition_manual.py
$LASTEXITCODE
```

有未提交改动时先保存并按团队指南同步，不直接拉取。首次命令将自动定位MSVC，不需要手工填写个人电脑的编译器路径；无需安装额外Python包，也不需要平台账号。

成功标准：7项均显示`PASS`，总结果`passed=true`，退出码0。结果含本次源码哈希；报告和编译日志自动写入仓库内忽略的`work/competition_manual/development/`。失败时先看报告的`error`，编译错误看`compile.log`；缺少工具链则补齐上述工作负载。不要把`passed=false`理解为测试成功。

| 用例 | 要检查的行为 |
| --- | --- |
| empty | 空列表立即报错，不进入平台帧循环 |
| defaults | 首点采用默认速度/kp，只建立一次初始路径 |
| explicit | 首点采用明确设置的速度/kp |
| interpolation | 插值模式也能建立初始路径 |
| transition | 首帧不跳过首点，后续能进入下一点，末点不越界 |
| fractional_stop | 0.5秒前持续发出停车命令，到时恢复，不重复停车 |
| reentry | 再次进入模式重置编号，不沿用上次最后一点 |

想观察原问题，可运行：

```powershell
py -3.10 tools/test_competition_manual.py --baseline
```

这是故障复现，预期退出码1，用例出现`invalid vector subscript`，总结果为false。报告保存在`work/competition_manual/baseline/`，不会覆盖修复版结果，也不会修改原件。

测试器复制完整`main_manual.cpp`到临时构建目录，只规范副本编码，让它引用测试用`main.h`。测试替身提供确定的位置、时钟和平台函数，用带边界检查的列表把旧版非法访问转成可读错误；不执行旧程序入口，不连接网络或启动仿真。每个用例在独立进程执行，reentry例外地在同一进程调用两次，专门检测遗留状态。

这些测试证明所列输入下真实循环的行为，不能证明SDK接口/二进制兼容、路径几何、制动性能或官方成绩。测试中时间按0.1秒推进，路径函数仅记录目标，不求解真实地图。

## 规则对应与正式验收

依据2027年第十届《评分与规则》物理第31页，评分编号41“城市道路场景”（表43）：15分钟内完成全部测试路段取得基础分1000，超时按里程折算；完全驶出道路或碰撞路障结束测试并按里程比例评分；限速路段超速扣200，碾压实线每次扣50，违反信号灯扣200；最大加速度不超过5m/s²加200；7分钟内完成，每少1秒加5分，不足1秒不计。

上述是未来连续场景的验收依据，不是对旧41.stg的编号映射确认。本轮代码对应的是策略执行前置条件：有效首点才能读取参数、空策略不能进入循环、配置的小数时间不丢失。验证对应上表离线用例，不涉及官方扣分阈值修改。正式比赛仍须按实际场景、最新通知逐项验证距离、速度、灯光、时限和车辆行为；0.5秒来自继承配置，不是本届规定停车时长。
