三组均以车身之间的距离为准，目标间距2m；验收容差±0.5m、停稳速度不超过0.1m/s均为辅助实验设定，不是赛事官方阈值。前车始终存在，完成驻停后继续制动，不放行撞向前车。

CSV逐帧数据与报告计时已交叉核对；每轮车辆和传感器清理成功，结束后服务端无实验actor、恢复异步模式。报告保存实验参数、源码/动态库哈希、平台版本、地图车型与失败原因；复现实验时同时记录`git rev-parse HEAD`。独立测量与控制器计时可不同：测量器按±0.5m范围计算，控制器在更窄的停车区域内启动；报告分别保留两者。

规则依据：2027《评分与规则》物理第13页表9驻停小于10s计零分；第19页表22、评分ID20驻停不超过5s计零分，因此不能把两种下界混用。对应的精确等号测试通过；这只验证计时能力，不等于完成相关泊车、信号灯或路口场景。策略`.stg`中的stopTime仍解释为最短驻停时间，逐场景如何配置需另行核定。

SimOne的[SimOne_Data接口说明](https://simone-docs.51sim.com/SimOneCpp/struct_sim_one___data/index.html)标明timestamp单位为毫秒；策略循环转换为秒使用，匹配本届SDK时仍需核对其时钟行为。GPS取数失败现在立即返回false，策略循环下发零目标速度并重置驻停计时；其他驾驶模式调用方和SDK发送失败处理尚待补齐。

以上三组使用Python接近规划器，仅共用C++驻停核心；复现时必须指定`--controller experimental`。它们不证明正式跟车算法达到同样效果。此前观察到的末段短暂停下后继续靠近属于这条实验链，不能据此推断正式跟车代码有同样行为。

## 如何复现本批能力

以下命令均在仓库根目录的PowerShell执行，先按团队指南准备64位Python 3.10和MSVC。离线验证无需启动仿真器：

```powershell
py -3.10 -B tools/test_competition_control.py
py -3.10 -B tools/test_competition_manual.py
py -3.10 -B tools/test_competition_neighborhood.py
py -3.10 -B -m unittest tests.test_competition_following tests.test_stationary_stop tests.test_stop_controller tests.test_lead_profile tests.test_competition_steering tests.test_stop_analysis -v
```

前三项应退出码0且`passed=true`，最后一项显示`OK`。报告位于`work/competition_control/development/`、`work/competition_manual/development/`和`work/competition_neighborhood/development/`。用`py -3.10 -B tools/test_competition_control.py --revision 7e27d29 --label following-before`可复现本批修改前3项失败，预期退出码1；只读取旧源码，不切换工作树。

CARLA实验需下载并解压[官方CARLA 0.9.15 Windows包](https://github.com/carla-simulator/carla/releases/tag/0.9.15)。以下客户端版本与服务端必须一致；CARLA只作辅助开发，不需要赛事平台账号。

首次创建专用Python环境并安装客户端，然后预先验证C++桥接能构建：

```powershell
py -3.10 -m venv work/carla/venv
.\work\carla\venv\Scripts\python.exe -m pip install carla==0.9.15
.\work\carla\venv\Scripts\python.exe -B tools/competition_stop.py
```

最后一条应输出DLL路径和哈希；失败时先处理MSVC组件或输出中的编译日志。各队员输入自己的CARLA路径，启动一个专供本实验使用的服务端：

```powershell
$carlaRoot = Read-Host '输入包含CarlaUE4.exe的目录完整路径（不加引号）'
& (Join-Path $carlaRoot 'CarlaUE4.exe') -quality-level=Low -carla-rpc-port=2000 -nosound
```

等待场景加载，在另一个仓库根目录PowerShell窗口运行：

```powershell
.\work\carla\venv\Scripts\python.exe -B tools/carla_stationary_stop.py --speed-kmh 10 --gap 25 --dwell-seconds 2
```

脚本默认`--controller formal-follow --steering formal --distance-geometry body`，连接本机2000端口，必要时加载Town01，生成主车、静止前车和记录相机。不要同时运行其他控制客户端；已有车辆/行人/传感器时会拒绝接管。首次调用自动编译正式函数DLL，默认实时展示，完成后实验车辆清理。上述10km/h、25m当前已通过，正常应显示`passed=true`并退出码0；`competition_verified`始终为false。若出现连接或编译错误则属于环境问题，按error排查，不能当作同一个算法失败。

终端会显示结果目录：`report.json`含参数、正式源码/动态库/配置哈希、失败原因、实际连续静止时间`stationary_seconds`和区内驻停时间`stop_held_seconds`；`frames.csv`同时保存`formal_target_speed_mps`与最终使用的目标；PNG为过程和结束截图。完成后关闭本轮启动的CARLA窗口。

用相同初始条件对比正式函数的旧几何与实际几何。`--no-realtime`取消实时显示等待，仍按仿真时间计时；第一条预期失败，第二条预期通过，两者制动公式与验收一致：

```powershell
.\work\carla\venv\Scripts\python.exe -B tools/carla_stationary_stop.py --controller formal-follow --distance-geometry legacy --spawn-alignment map-spawn --speed-kmh 30 --gap 60 --no-realtime
.\work\carla\venv\Scripts\python.exe -B tools/carla_stationary_stop.py --controller formal-follow --distance-geometry body --spawn-alignment map-spawn --speed-kmh 30 --gap 60 --no-realtime
```

已按上面的步骤启动CARLA后，可在仓库根目录复现新增前车制动实验：

```powershell
.\work\carla\venv\Scripts\python.exe -B tools/carla_stationary_stop.py --scenario lead-brake --no-realtime
```

当前默认显式策略预期退出码0、`passed=true`，报告中的`braking_assessment`应显示`cruise_matched`与`stop_passed`均为true。增加`--following-policy legacy`复现旧策略匀速失败（预期退出码1）；增加`--fixed-delta-seconds 0.1`验证另一采样条件。速度与间距容差未调宽；若道路、车型或错误原因不同，应按实际报告分析。报告与逐帧CSV保存在终端输出的结果目录。前车不会重新起步，恢复行驶用独立的`--scenario stop-go --speed-kmh 30 --gap 15`实验验证。

固定道路与出生点（同一服务端须逐条运行，等待上一条结束）；第一条默认开启缓升，追加`--max-target-rise 0`可对照原请求：

```powershell
.\work\carla\venv\Scripts\python.exe -B tools/carla_stationary_stop.py --scenario lead-brake --road-id 15 --lane-id -1 --spawn-index 224 --no-realtime
.\work\carla\venv\Scripts\python.exe -B tools/carla_stationary_stop.py --scenario lead-brake --road-id 15 --lane-id -1 --spawn-index 224 --spawn-alignment map-spawn --no-realtime
```

第一条居中起步预期通过；第二条保留旧起点，预期退出码1并报告走廊保护失败。出生点编号只对应本实验Town01地图；报告中的`spawn_index`、`spawn_setup`和`last_observation`可核对实际起点与触发保护的观测。
